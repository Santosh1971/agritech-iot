# MQTT Interface

## TH Bulletins

These are transmitted periodically as defined by the `TempInterval` parameter
without any prompting by the platform.
These are sent to all the applicable topics.

```json
{
  "payloadId":"TH",
  "Temp":29.9,
  "Humi":75,
  "ts":"2019-08-23T01:24:10.000Z",  // when it was measured; different from Date when NOT live
  "seqNum":0, // sequence number is 0
  "live":1, // live is 1 usually; 0 if it is delayed due to any communication issue
  "Date":"2019-08-23T01:24:10.000Z",
  "mac":"5ccf7f3d7c3a"
}
```

## GetTH Command

This is the command to get TH on demand.

> Command

```json
{"payloadId"  : "GetTH", 
"Token" : "4d350975-4d01-4f8d-82be-14a84edd952c",
"Date" : "7/1/2019 16:20:51",
"mac" : "5ccf7f3d79d7_110"}
```

> Response

It is the same as the [TH bulletin](#th-bulletins)'s payload, with some refinements as below.
  * Token of the request is sent in addition.
  * The response is not sent to both topics as in the monitored responses. It is sent only to the topic matching the rxtopic from where the command was received.

```json
{
  "payloadId":"TH",
  "Temp":29.9,
  "Humi":75,
  "ts":"2019-08-23T01:24:10.000Z",
  "seqNum":0, // sequence number is 0
  "live":1, // live is always true
  "Token":"4d350975-4d01-4f8d-82be-14a84edd952c",  // token of the request is added
  "Date":"2019-08-23T01:24:10.000Z",
  "mac":"5ccf7f3d7c3a"
}
```

## SetParameter Command

This command allows user to change all or subset of configuration parameters of the device.
At present the parameters comprise (i) TempInterval(in seconds) and (ii) StoreLimit(in #rows).
Changes are affected immediately.

> Command

```json
{
  "payloadId"  : "SetParameter", 
  "Token" : "4d350975-4d01-4f8d-82be-14a84edd952c",
  "TempInterval" : 60,
  "StoreLimit" : 100,
  "Date" : "7/1/2019 16:20:51",
  "mac" : "5ccf7f3d79d7_110"
}
```

> Response

The usual Acknowledgement with the token with a textual indication of what has
been set is sent back.

## Other Common Interactions
### Common Commands
Below commands are also supported, with `payloadId`s as given.

* `SetTime`: Set current date and time of the device
* `SystemReset`: Reset the device using `ESP.reset`
* `SystemUpgrade`: Upgrade the device using OTA
* `SystemInfo`: Restart the connection with the platform/broker

### System Information Payload

The below payload is generated by the device on startup describing itself and
its basic configuration parameters.

```json
{
  "mac": "5ccf7f3d7c3a",
  "ip": "192.168.43.97",
  "PCB": "5x5-WemosRTC-Master",
  "Date": "Oct 14 2019 - 11:14:23",
  "File": "THMonitor.ino",
  "Version": "Release/v03",
  "TempInterval(seconds)": "60",
  "StoreLimit(rows)": "100"
}
```

# Serial Commands

The below commands are supported by sending text through the serial interface.
Each command follows the below format.
```
<keyword> <argument1> <argument2>.....
```
where `keyword` is a single character identifying the command (such as `r` for restarting the device),
and `argument1/2` etc. are the commands arguments (which may or not be required as per the `keyword`).

The commands are supported are:

* `r`: restart the ESP device (by calling `ESP.restart()`)

* `W`: Disconnect WiFi and erase existing credentials. The device will do a fresh reconnect as expected.

* `W <ssid> <password>`: Connect to a specific WiFi access point identified by its `ssid` with a `password`. Disconnect if already connected to an access point. Use the new connection for MQTT communications etc.

* `T 0|1|2`: change the topic stage respectively to `dev|test|prod`
> Note: you will need to restart the device for the change to take effect.

* `E`: reset EEPROM marker, so that its contents are reinitialized on next restart.
> Note: you typically restart the device after this.

* `e`: dump variables mapped to EEPROM to the console for debugging.

* `Q <mqttpayload>`: send a mock MQTT payload for testing purposes
